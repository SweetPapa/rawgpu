# Vendored: amdgpu powerplay (SMU7 / Polaris 10)

`upstream/` holds files from Linux `drivers/gpu/drm/amd/`, **byte for byte**,
at torvalds/linux `05441d697f7f9a927264f4058cbbc6a03dfcac9d` (the commit the
register headers and the ATOM interpreter come from). They are MIT-licensed by
AMD; see each file's header. The plan and the reasons are in `docs/DPM.md`.

| Directory here | Upstream |
|---|---|
| `upstream/hwmgr/` | `pm/powerplay/hwmgr/` |
| `upstream/smumgr/` | `pm/powerplay/smumgr/` |
| `upstream/inc/` | `pm/powerplay/inc/` |
| `upstream/legacy-dpm/` | `pm/legacy-dpm/` |
| `upstream/include/` | `include/` (and `include/drm/amd_asic_type.h` from the top-level `include/drm/`) |

Only the Polaris 10 path is carried. `rg_pp_stubs.c` gives the other chips'
function tables, which `hwmgr.c` names, empty bodies that fail loudly.

## How it compiles unmodified

- `shim/` provides the kernel and amdgpu headers the files include.
  `rg_pp_kcompat.h` has the kernel API, and `amdgpu.h` has a minimal
  `struct amdgpu_device`, with only the fields this code reads.
- `asic_reg/` is generated by `tools/gen_pp_regs.py`: the upstream register
  headers, trimmed to the names this code can reach. The objects are
  byte-identical to a build against the full headers (128 KB instead of 8.6 MB).
- `rg_pp.c` is rawgpu's glue. It stands in for `amd_powerplay.c` (create,
  early, sw, hw and late init), `amdgpu_cgs.c` (register access) and the few
  `amdgpu_*` helpers. `rg_pp.h` is its interface to the rest of rawgpu.
- The flags match the kernel's: `-fno-strict-aliasing -Wno-pointer-sign`.
